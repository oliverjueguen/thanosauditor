## `bundles/`: REAL data from Practice 1 (P1)

| File | Run | Binaries |
|---|---|---|
| `2026-04-patch-tuesday-full.bundle.json` | "2026-04 Patch Tuesday FULL": full run, 2026-05-07 21:57 UTC | 85 |
| `2026-04-patch-tuesday-reparto.bundle.json` | "2026-04 Patch Tuesday": split run, 2026-05-07 17:52 UTC | 7 |

Generated by the team with the executor (Ghidra headless) on the DLLs rebuilt
from the KB5078766 → KB5082142 pair. They were **sanitized** with `python -m thanos.core.sanitize`
(`C:\Users\...` paths → `<runner>\`: 170 and 14 paths); the analysis data was not
modified. The `person` field of each bundle keeps the executor's alias because the
product uses it (split and panel).

**Cross-check:** `diagnostic.dll` and `wdsclient.dll` appear in both
runs with identical SHA-256 and counts (functions, exports, imports, strings), which
shows with real data that reconstruction and analysis are reproducible
(`tests/test_core.py::test_reconstruction_is_deterministic_across_runs`).

**No copy was kept** of the other bundles from the split run. The P1 panel
(screenshot in the report, page 14) shows that they existed, but their data cannot be
recovered from these two.

## `msrc/`: official Microsoft CVEs (MSRC)

`2026-Apr.ws2022.json`: extract of the 115 CVEs that affect Windows Server 2022 in the April 2026
CVRF bulletin (`https://api.msrc.microsoft.com/cvrf/v3.0/cvrf/2026-Apr`, retrieved on
2026-10-13), generated with `thanos.ontology.msrc.extract_cves`. To regenerate it live:
`python -m thanos.ontology.cli ingest-cvrf --live 2026-Apr`.

## `catalog/`: real responses from the Microsoft Update catalog

## `synthetic/`: SYNTHETIC data (tests only)

`*.SYNTHETIC.bundle.json` (field `"synthetic": true`): created by hand for the automated
tests that need several people in the same cycle. **They are not real
results** and neither the demo nor the panel uses them.
